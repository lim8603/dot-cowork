# 실제 협업 산출물 검토 — 2026-09-20

## 범위와 판단 기준

dot-cowork 1.3.0의 한국어·영어 원본과 로컬 설치본 두 곳을 비교했다. dot-probe HEAD는 `0241c828`, dot-tools HEAD는 `7a60186`이었다. 두 설치본의 `upgrade_manifest.md`는 모두 프레임워크 1.3.0을 표시한다. Tools 제품 버전 1.3.1과 프레임워크 버전은 별개다.

공유/개인 상태, 진입점, 최근 세션 로그, ADR 등록 구조, 검증 근거, KB, 회고, 배포 문서 목록을 읽고 일부 기록을 코드와 대조했다. 모든 과거 로그·반입 소스·제품 기능을 전수 감사한 것은 아니다. 테스트 성공 수치와 게시 결과는 당시 기록이며 이번 검토에서 제품 테스트나 외부 게시 상태를 재검증하지 않았다. 두 프로젝트에는 변경을 가하지 않았다.

아래 경로는 각 프로젝트 루트 기준이다. 세션 로그는 로컬에 존재하더라도 배포/버전 관리에서 제외될 수 있다. 이 문서는 핵심 관찰만 남기고 원문 전체를 복사하지 않는다.

## 구조와 실제 사용

프레임워크는 Define → Design → Build → Verify → Evolve/Deliver의 기준 문서, ID별 상세 문서와 registry, 공유/개인 상태, 원문 로그를 분리한다. 이 구분은 유지할 가치가 있다. 이번 문제는 폴더 부족보다 기존 문서가 자기 역할을 벗어나거나 갱신 시점을 놓치는 데서 나타났다.

| 관찰 | dot-probe | dot-tools |
|---|---|---|
| 규모/흐름 | Rust 서버·클라이언트·설계 반입이 병행되는 장기 Build | VS Code 확장의 구현·실사용 수정·반복 배포, 상태상 Evolve |
| 공유 상태 | 205,429 bytes / 487행 | 81,537 bytes / 341행 |
| 개인 상태 | lim8603: 44,863 bytes / 173행 | Seunghyun: 18,811 bytes |
| KB | 150,440 bytes / 242행 | 44,009 bytes / 94행 |
| 상태 문서의 800자 초과 물리 행 | 공유 41행, 개인 6행 | 공유 14행, 개인 0행 |

UTF-8 파일 전체 bytes를 측정했다. 긴 한 행 안에 여러 세션이 들어가므로 행 수만으로 문서 부담을 판단하기 어렵다. 24/12 KiB와 800자는 이번 개선의 **초기 경고값**이며 최적값으로 실증된 수치가 아니다. 프로젝트별 조정을 허용한다.

## 유지할 부분

1. **결정에서 실제 변경까지 추적된다.** Probe의 9/18 로그는 ADR-074, 마이그레이션 0072, 서버·클라이언트·번역 변경, 로컬 검증을 연결한다. 단순 대화 기억보다 복원성이 높다. 근거: `.cowork/members/lim8603/workspace/session_logs/session_2026-09-18_001.md`와 `.cowork/03_design_artifacts/adr_registry.md`.
2. **실사용 확인이 자동 테스트의 빈틈을 찾는다.** Tools #021은 폴더 설정의 침묵 결함을 Human 제보로 찾고 선언과 소비 코드를 함께 수정했다. `package.json`의 resource scope와 `src/core/adapterRegistry.ts`의 폴더별 `workspaceFolderValue` 읽기가 현재 코드에서도 확인된다. 근거: `.cowork/members/Seunghyun/workspace/session_logs/session_2026-08-28_021.md`.
3. **불완전한 검증을 기록할 수 있다.** Probe는 전체 CI 지연을, Tools는 멀티루트 통합 테스트 한계와 WSL 잔여 위험을 남겼다. 예외를 없애기보다 상태와 판정에서 잘 보이게 해야 한다.
4. **산출물이 실제 배포에 연결된다.** Tools에는 `docs/`의 번호별 문서, README, CHANGELOG와 버전별 검증 기록이 있다. 문서 체계를 전부 없애면 이 인계·배포 기반도 사라진다.

## 반영 범위와 릴리즈 경계

- 한국어/영어 프레임워크 원본, README/DESIGN, 문서 맵·기능 점검표, Unreleased 변경 기록을 동기화했다.
- 검토 후 릴리즈 대상은 1.4.0으로 확정했다. 양쪽 매니페스트에 1.3.0 → 1.4.0 델타를 추가하고, 기존 프로젝트 데이터와 진입점은 MERGE로 보존한다.
- prepare/verify와 한국어·영어 아카이브 재생성으로 배포를 준비한다. 두 소비 프로젝트의 실제 업그레이드는 이 릴리즈와 별도로 수행한다.

## 이번 변경의 확인 결과

- 한국어·영어 템플릿 구조 검사 및 Markdown 문자 깨짐 검사 통과.
- 기존 1.3.0 버전/매니페스트/누적 블록 정합성 검사 통과. 이는 미출시 변경의 업그레이드 델타·배포 검증을 대체하지 않는다.
- 크기 점검 스크립트의 임시 fixture 9사례 통과: byte 경계, UTF-8, 긴 행, 개인 상태, 공백/대괄호 경로, 누락 상태 오류, 기본 보고와 `-Check` 종료 코드. 실행 전후 fixture 해시 동일.
- 두 실사용 프로젝트의 공유/개인 상태에서 경고를 탐지했고, 양쪽 프레임워크의 빈 공유 상태 템플릿은 기본 경고선 이내였다.
- 규칙 정합성 검토: 8개 진입점 참조 전환, R1/R2와 아카이브 설명, solo 초기화, 검증 인덱스와 Gate 판정 규칙을 함께 확인했다.
